# AGAPAY Phase 8 (Report Generation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any role can generate the distribution monitoring report for one distribution cycle, as a PDF or an Excel file. The report can be narrowed by program (All / DA / LGU) and by distribution date. It contains:
- per-intervention assigned, claimed and unclaimed counts, with the quantity distributed;
- a per-barangay breakdown;
- the beneficiary list;
- the inventory used.

Every generated file is kept in a history the user can download again. The page matches Figma 340:51, 407:1694 and 470:2205.

**Architecture:**
- **Data:** `ReportService::build(ReportCriteria): array` gathers the data. It is pure queries, with no rendering.
- **Generation:** `ReportService::generate(ReportCriteria, User): GeneratedReport` renders the PDF (DomPDF view) or the .xlsx (a multi-sheet maatwebsite export). It stores the file privately and writes a `generated_reports` row plus an audit row.
- **Page:** `ReportController` serves the form, the generate action and re-downloads.

**Tech Stack:** Laravel 13 / PHP 8.5, DomPDF 3.1, maatwebsite/excel 4, Pest 4, Blade + Tailwind 4 + Alpine 3.

**Spec:** `docs/superpowers/specs/2026-09-28-agapay-design.md`, sections:
- §3: the `/reports` row;
- §4: `generated_reports`;
- §5: rules 2 and 12;
- §6: Phase 8, steps 42–45.

**Paper:** §1.4.1 Scope (lines 757–764 of the text extract): reports are generated "exclusively" for scheduled distribution events (cycles); ad hoc handouts must first be encoded into a schedule.

**Builds on:**
- Phase 4: `InterventionRecord`, `DistributionCycle`.
- Phase 5: `InventoryMovement` (AUTO movements linked to records).
- Phase 7: the DomPDF export pattern and the 512M memory note.

**Which records a report includes**
- Non-archived intervention records of the chosen cycle.
- The program filter matches the intervention's source.
- With a date range, a record is included when it is unclaimed, or when it is claimed with `date_distributed` inside the range (inclusive).
- Validation errors:
  - End before start → "The end date cannot be before the start date."
  - Any date after today → "Dates cannot be in the future."
  - Unknown cycle → "Choose a distribution cycle."

**Report contents (`build()` returns this shape)**
- `criteria` (an array of labels for the header).
- `summary`: `{beneficiaries, assigned, claimed, unclaimed}`, where beneficiaries counts distinct people.
- `interventions`, a list sorted by source then name. Each row has: `source` ("DA"/"LGU"), `name`, `unit`, `assigned`, `claimed`, `unclaimed`, and `quantity` (Σ quantity of claimed records).
- `barangays`, a list sorted by name. Each row has: `name`, `beneficiaries`, `assigned`, `claimed`, `unclaimed`, `quantity`.
- `beneficiaries`, a list sorted by barangay, last name, first name, then intervention. Each row has:
  - `name`, `rsbsa` (or "(pending)"), `barangay`;
  - `program` ("DA - Certified Rice Seeds"), `quantity`;
  - `validation` (its label), `claim` ("Claimed"/"Unclaimed"), and `date` ("M j, Y" or "—").
- `inventory`, sorted by item name. Each row has `item`, `unit_label` and `used`: the net AUTO quantity (out − in) linked to the included records, skipping items whose net is 0.

**Output formats**
- **PDF:** A4 landscape. Header "Office of the Municipal Agriculturist — Bontoc" / "Distribution Monitoring Report", then the criteria line, then the four sections with headings. Footer "Generated by {name} on {M j, Y g:i A} · AGAPAY".
  - The beneficiary list stops at `config('agapay.report_pdf_max_rows', 1000)` rows, with the line "Showing the first N of M beneficiary rows — choose Excel for the full list."
  - `memory_limit` is raised to 512M during generation.
- **Excel:** sheets "Summary", "Per Intervention", "Per Barangay", "Beneficiaries" and "Inventory Used". Figures are numeric cells, text cells are explicit text, and there is no row cap.

**Files and history**
- **File name:** `agapay-report-{cycle-code}-{all|da|lgu}-YYYY-MM-DD.{pdf|xlsx}`.
- **Storage:** private `local` disk, `reports/{id}.{ext}`.
- **`generated_reports` table:** id; user_id FK; distribution_cycle_id FK; program string(3); start_date and end_date (nullable dates); format string(4); file_name; path; rows (int, the number of beneficiary-list rows); timestamps.
- **History** ("Generated Reports" card, below the mirrored region):
  - the 10 most recent, paginated;
  - Admin sees everyone's reports; AT and DE see only their own;
  - columns: Generated, By, Cycle, Program, Dates, Format, Download.
  - Downloading is limited to the same people (others get 404). A missing file → 404 page with "This report file is no longer available — generate it again."
- **Audit:** "Generated Distribution Report", with the record label = file name and new values `{cycle, program, start, end, format, rows}`.

## Review Focus

1. **A cycle with thousands of records.** The PDF must not run out of memory: the row cap applies and the summary covers all rows. Excel lists everyone (Task 2).
2. **Date filters people type.** Examples: start after end, future dates, only one date given, a forged cycle id or program. Expected: field errors or defaults, never a 500 (Tasks 1, 2).
3. **Archived records and later changes.** Archived records are excluded. An unclaimed record that is claimed later appears in the next report. A history download returns the file as generated, not recomputed (Tasks 1, 2).
4. **Privacy across roles.** An encoder cannot download another user's report by changing the id (Task 2).
5. **Totals that agree.** Σ per-intervention = Σ per-barangay = summary = beneficiary-list counts, and inventory used matches the stock movements (Task 1).
